# A Go client, and what a second client is for

- **Date:** 2026-09-13
- **Author:** Claude (Opus 5)
- **Touches:** `clients/go/` (new)
- **Kind:** feature

## What changed

A Go module at `clients/go`: generated protobuf under `internal/pb`, a hand-
written `slate` package with values, expressions, queries, sessions,
transactions, single-table `Explain` and a typed error taxonomy, and sixteen
tests that run against a real `slate-serverd` built from this tree.

## Why

Second on the README's not-built list, and cheaper than it was: `slate-serverd`
is a real binary now, so the tests write a TOML file and start a process rather
than reimplementing server startup the way the Python client's `testserver`
crate had to.

The deeper reason is the one the Python client's conftest gives about mocks,
turned outward: a *second* client is the first real check that the protocol is
a protocol rather than one client's habits written down. Where Go and Python
disagree about what a message means, one of them is wrong.

## Alternatives rejected

**`any` for column values.** Idiomatic Go and wrong here: `Uint(7)` and
`Int(7)` are different values to this server, whose ordering is type-first, so
a client inferring from a Go `int` writes rows that cannot be found again. The
closed `Value` interface makes the compiler ask.

**Column names instead of ordinals.** Would mean this client holding a second
copy of the schema, which can disagree with the server's. Positions are what
the wire carries.

**A builder chain (`Query().Table("x").Limit(2)`).** Go composite literals
already read as a builder, and a chain needs a second way to say "no limit"
that is not the zero value. `Limit(n)` returning `*uint64` keeps nil meaningful.

**Generating the client from the proto.** The generated stubs are the transport
and are in `internal/pb`; a hand-written surface is where the *decisions* live
— that a missing row is `found == false` rather than an error, that a session
carries a watermark, that rollback after commit is quiet.

**A mock server for the tests.** Refused for the reason the Python suite gives:
a mock is a second statement of what the server does, written by whoever wrote
the client, so it agrees with the client's misunderstandings.

## Evidence

Sixteen tests, all passing against a real node, `go vet` and `gofmt` clean.
Five mutations, all killed — but two only after the tests were strengthened:

- Dropping the upsert flag, ignoring a descending sort, and dropping the
  projection each fail immediately.
- **Dropping `WriteResult.Sequence` survived**: no test asserted the field,
  only the session watermark that is set beside it. `TestInsertThenGet` now
  checks it.
- The watermark mutation I first wrote did not actually disable the watermark
  — it removed the `WriteResult` field, which is how the gap above surfaced.
  Mutating the real line, and asserting that a *second* write advances it
  further rather than merely setting it once, kills it.

`TestEveryValueKindRoundTrips` writes all seven scalar kinds plus a UUID and
asserts each comes back as itself, including that `Int(-5)` and `Uint(5)` do
not decode to the same value.

## What this does not do

`Join`, `Aggregate` and `ExplainJoin` are on the wire and have no typed surface
here — the generated stubs make them reachable, but there is no builder and no
test, so they are stated as absent in the README rather than half-present. No
vector similarity, no `SchemaCheck`, no computed values in a query.

Nothing here is a differential *against the Python client*. Both are tested
against the same server, which catches a client that is wrong about the
protocol; it does not catch two clients that are wrong in the same way.

The tests need `cargo` on the path and build the daemon, so this suite is not
runnable from a Go-only checkout.
