# A site: two static pages, and quickstarts that were run before they shipped

- **Date:** 2026-09-13
- **Author:** Claude (Opus 5)
- **Touches:** `site/` (new)
- **Kind:** feature

## What changed

`site/index.html`, `site/docs.html`, one stylesheet and a README. No build step,
no dependencies, no generator.

## Why

Nothing is being sold, so the site's whole job is to get someone from "what is
this" to a working SDK call. That is a landing page with quickstarts and a page
of concepts — the shape slatedb.io uses, minus the parts that need adoption to
be worth showing.

## Alternatives rejected

**A static-site generator.** The standard answer, and wrong at this size: it
adds a toolchain to install, upgrade and eventually migrate, in exchange for
templating two files that share one `<header>`. The trade flips at about ten
pages or when content wants to be Markdown; the README says so, so the next
person knows the decision was made rather than defaulted into.

**Duplicating the design notes into the site.** The repository already has five
of them, and a copy is a copy that goes stale. `docs.html` covers the five
things that make the client APIs make sense — ordinals, the type-first value
model, that the node does not authenticate, session watermarks, and the error
kinds — and links out for everything else.

**A logo wall, an adoption count, a comparison table.** Nothing to put in them.
The README for the site lists them as deliberately absent so nobody adds one
later assuming it was an oversight.

**Claiming production readiness by omission.** The "What it is not" section
leads with *not production-proven*, because a landing page that lists
correctness work and stays quiet about operational history is making a claim by
implication.

## Evidence

Checked in a real browser at 1280px and 420px: no console errors, no horizontal
scroll at either width, and the quickstart tabs actually switch panels.

**The three quickstarts were extracted from the page and executed.** A head node
was started from the TOML in the fourth tab — the same text a reader would copy
— and each snippet run against it verbatim. All three insert a row and read it
back. This caught nothing, which is the point: it is the check that would have
caught a wrong method name, and running it is cheap compared to shipping example
code that does not compile.

The one failure during that run was the TypeScript snippet returning
`already-exists`, because the Python and Go runs had already taken the key. That
is the snippet being right.

## What this does not do

**The quickstarts are not checked automatically.** Nothing re-extracts and runs
them, so they can rot the moment a client's API changes. That is the obvious
next thing and it is not here; the site README says so rather than leaving it
implied.

No deployment. The site is files in a directory; nothing publishes them.

No search, no versioning, no dark/light toggle — it is dark, on the grounds that
the thing it most resembles is a query console.

The landing page asserts things about the project that are true today and are
not tested. The README asks whoever changes the project's behaviour to change
the page too, which is the weakest kind of guarantee.
