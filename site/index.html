Rows, indexes and a planner on top of object storage.

slate is a record layer: it turns an ordered key–value store into tables with secondary indexes, a cost-based query planner, joins, aggregates, and row-level security that is compiled into the scan rather than checked around it.

One head node speaks gRPC. Clients for Python, Go and TypeScript speak to it.

Quickstart

Start a head node from a TOML file, then talk to it. Every client holds its own copy of the schema and the server checks it on each request, so a declaration that disagrees with the catalog is refused rather than answered with the wrong column. 

from slate import Client, Column, Identity, Query, Table, ValueType, desc, u64

BOOKS = Table("books", [
    Column("id",        ValueType.U64),
    Column("author_id", ValueType.U64),
    Column("title",     ValueType.STR),
    Column("year",      ValueType.I64),
], primary_key=["id"])

with Client("127.0.0.1:7421", identity=Identity("u64:1", roles=["app"])) as client:
    session = client.session()
    session.insert(BOOKS, [[u64(10), u64(1), "A Wizard of Earthsea", 1968]])

    query = Query(BOOKS)
    query.where(query.c.year.ge(1960)).sort(desc(query.c.year)).limit(20)
    for row in session.query(query):
        print(row)

What it does

Rows on a KV store

An order-preserving tuple codec puts rows and secondary index entries in one keyspace. Index maintenance is atomic with the write.

A planner that costs

Table scans, index scans, point gets, ranges from IN lists and LIKE prefixes, covering scans that never touch a row, and histograms for range selectivity.

Joins and aggregates

Hash and index nested-loop, cost-chosen, all four join types, chains of three or more tables, grouped joins and grouped chains, ordered and limited over groups.

Security in the kernel

RBAC and row policies are compiled into the predicate the executor evaluates and the bounds it scans — not checked by a wrapper a caller could route around.

One writer, many readers

A lease-fenced writer and read replicas, with read tokens so a session never reads its own writes backwards.

Three clients

Python, Go and TypeScript, tested against a real head node and against each other — one contract, three SDKs, identical answers.

How it is built

The interesting part of this project is not the feature list, it is the evidence. Most of what is here exists because a test found it.

  • Oracles, not examples. Every plan agrees with a full scan. Every join algorithm agrees with every other. A grouped join agrees with folding the join by hand. An n-way chain agrees with nested two-way joins.
  • Mutation testing. Changes are checked by breaking them and requiring a named test to fail. Several tests exist only because a mutation survived — and several of those revealed a test whose assertion the bug also satisfied.
  • Crash and fault injection. Torn writes, object-store failures, overlapping writers across a lease change, and a restart suite over the S3 path.
  • An adversarial security review, with each finding either fixed and pinned by a probe, or closed as inherent with the claim it contradicted narrowed to the truth.
  • A ledger. Every change carries an entry saying why it exists, what it was weighed against, and where it stops. A pre-commit hook refuses the commit otherwise.

What it is not

Not production-proven. Nothing runs this in anger. The correctness work is real and the operational track record is zero.

No SQL. Queries are built from typed client APIs. There is no parser and no plan for one.

No in-place promotion of a read replica to writer — promotion is a restart. No multi-writer. No cross-shard transactions, because there is no sharding.

The repository's README keeps a list of what is not built, and it is kept honest: an item is removed when it is built, or withdrawn in writing with the reasoning that retired it.

See it working

The explorer is an interactive demo: one database, three SDKs, and a switch that swaps which client library serves the request. A second switch changes who the database thinks is asking, so a row policy visibly takes rows away and a role without the right grant is refused — none of it enforced by the demo.
