Getting started

A record layer, not an ORM.

slate puts typed schemas, secondary indexes, a cost-based query planner and row-level security on top of SlateDB — an LSM key-value store that lives on object storage. The closest blueprint is FoundationDB's Record Layer. The derive macro is a surface; the value is in the kernel underneath it, which owns the keyspace, index maintenance, and the point where access policy is enforced.

Status: early. The Rust record layer works end to end and is tested, including a cost-based planner, index-only scans, joins, aggregates, read replicas and S3-compatible storage. There is a gRPC head node with writer leadership, and typed Python, Go and TypeScript clients over it, each tested against a real daemon and required to agree with the other two. Nothing here is published to a package registry and none of it is production-ready.

Where to start

If you want to see it work, the workbench is the kernel compiled to WebAssembly, running in your tab over 100,000 real New York taxi trips, with the planner's EXPLAIN beside every answer. There is no server behind it.

If you want to build something, the quickstart starts a head node from one TOML file and talks to it from three languages. Read five things to know first before the API surprises you — the client libraries are small, and they make more sense once those are clear.

If you want to know whether it is any good, start with what it is not. The repository's docs/correctness.md and docs/performance.md carry the worked examples, including several where a claim was measured and then withdrawn.

How it is put together

The interesting part of this project is not the feature list, it is the evidence. Most of what is here exists because a test found it.

  • Oracles, not examples. Every plan agrees with a full scan. Every join algorithm agrees with every other. A grouped join agrees with folding the join by hand. An n-way chain agrees with nested two-way joins.
  • Mutation testing. Changes are checked by breaking them and requiring a named test to fail. Several tests exist only because a mutation survived — and several of those revealed a test whose assertion the bug also satisfied.
  • Crash and fault injection. Torn writes, object-store failures, overlapping writers across a lease change, and a restart suite over the S3 path.
  • An adversarial security review, with each finding either fixed and pinned by a probe, or closed as inherent with the claim it contradicted narrowed to the truth.
  • A ledger. Every change carries an entry saying why it exists, what it was weighed against, and where it stops. A pre-commit hook refuses the commit otherwise.

Seeing it work

The explorer is an interactive demo: one database, three SDKs, and a switch that swaps which client library serves the request. A second switch changes who the database thinks is asking, so a row policy visibly takes rows away and a role without the right grant is refused — none of it enforced by the demo. 

git clone https://github.com/howlerops/slate-orm
cd slate-orm/examples/explorer && ./run.sh

For the kernel alone, with nothing to install, the workbench runs it in your browser: the same planner and executor, driven from a query editor, over a real month of New York taxi trips, with the plan beside every answer.
