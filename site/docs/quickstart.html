Getting started

Quickstart

Start a head node from a TOML file, then talk to it. Every client holds its own copy of the schema and the server checks it on each request, so a declaration that disagrees with the catalog is refused rather than answered with the wrong column. 

from slate import Client, Column, Identity, Query, Table, ValueType, desc, u64

BOOKS = Table("books", [
    Column("id",        ValueType.U64),
    Column("author_id", ValueType.U64),
    Column("title",     ValueType.STR),
    Column("year",      ValueType.I64),
], primary_key=["id"])

with Client("127.0.0.1:7421", identity=Identity("u64:1", roles=["app"])) as client:
    session = client.session()
    session.insert(BOOKS, [[u64(10), u64(1), "A Wizard of Earthsea", 1968]])

    query = Query(BOOKS)
    query.where(query.c.year.ge(1960)).sort(desc(query.c.year)).limit(20)
    for row in session.query(query):
        print(row)

import { Client, ge, int, uint, str } from "@slate-orm/client";

const client = Client.connect("127.0.0.1:7421", {
  principal: "u64:1",
  roles: ["app"],
});

const session = client.session();
await session.insert("books", [uint(10), uint(1), str("A Wizard of Earthsea"), int(1968)]);

for await (const row of session.query({
  table: "books",
  filter: ge(3, int(1960)),
  sort: [{ column: 3, direction: "desc" }],
  limit: 20,
})) {
  console.log(row);
}

What the check does with this page

These four panels are not illustrations. site/check/quickstarts.py extracts them from this file, starts a head node from the TOML, and runs all three snippets against it on every push — because a quickstart is the first thing a reader tries and the last thing anybody edits when an API changes.

Two things it does to make that honest. The TOML names an S3 bucket, which cannot be started in CI, so it is validated verbatim by slate-serverd --check and then run with only the [storage] stanza swapped for memory — and the swap is asserted to touch nothing else. The snippets name a fixed port; each run picks a free one, and the substitution is asserted to fire exactly once, so a snippet that stops mentioning the address fails rather than quietly connecting somewhere else.
